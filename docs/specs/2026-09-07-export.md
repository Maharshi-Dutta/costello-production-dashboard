# Export to Excel or PDF (spec, approved by the user 2026-09-07)

## Product context
Costello Windows runs its factory from one SharePoint workbook (`Production` sheet).
This dashboard (`d:\Costello Windows\Excel Dashboard\web`: static site, plain ES2017
browser JS, no bundler/modules; `index.html`, `app.js`, `parser.js`, `graph.js`,
`checkpoints.js`, vendored MSAL + ExcelJS, and now vendored `vendor/pdfmake.min.js` +
`vendor/vfs_fonts.js`) reads the workbook by downloading it. Jobs are parsed into
objects (see `parseWorkbook` in parser.js): `id, cust, area, eir, off, colour, ph3, wnd,
drs, dates{sold,stamp,ivana,ready,floor}, prods[{n,f,s,t,st}], glass{type:n}, notes[{k,t,s}],
sheets[], urg, done, cat, blk, seq, stage, cp{...}`; checkpoint state via `itemState(j,item)`
and `cpItems(j)` (checkpoints.js); comments via `commentsFor(id)` (app.js, from the log);
sections via `BLOCKNAMES` and `j.blk`; alerts via `alertsFor(id)` (app.js).

The feature: a person downloads the jobs they choose as an Excel workbook or a PDF, with
filters and a field picker, straight to their device. No email.

User's answers (binding):
1. Delivery: direct download only (Excel via ExcelJS already in the app; PDF via the
   vendored pdfmake, one click, no print dialog).
2. **Content: no phone numbers and no eircodes anywhere, ever.** Customer name and county yes.
3. Every export is logged in the Dashboard Log: who, format, job count, filters.
4. Company name and logo in the PDF header (logo file arrives later: design a slot that
   shows the name alone when `assets/logo.png` is absent; never fail on a missing logo).
5. Windows, doors and components must be shown in a very visual, instantly readable way.

## HARD RULES
- The export code must never read or emit `ph3`, `eir`, the sheet's PHONE NO. or EIRCODE
  columns, or any field containing "phone"/"eircode". A standing test asserts that no
  exported cell, string or PDF text node contains those field values or header names.
- No network calls of any kind in the export path (no Graph reads; it works on the data
  already loaded). The ONLY write is one Dashboard Log line per export via `noteChange`
  (job `"(export)"`, what `"Export"`, from `"<PDF|Excel> · <n> jobs"`, to the filters
  summary). Nothing else is written; nothing is stored except named presets in
  localStorage under `cw_exportpresets` (presets only: filters/fields/format, never job data).
- No real address, name or domain in code or tests beyond the existing page title.
- Offline tests only (vm-loaded pattern of `test_checkpoints.js` / `test_alerts.js`), no
  commits, keep every existing check green (`node --check` on all JS, `test_move.js`,
  `test_checkpoints.js`, `test_alerts.js`, `verify.js`, `automation/test_digest.js`).
- Plain ES2017, no modules; theme-aware CSS with the existing variables; 40 px tap targets.

## Files
- New `export.js` (loaded after checkpoints.js, before app.js; add to `build.py`'s
  cache-busting regex). Pure logic first, all testable in Node:
  - `exportFilter(jobs, f)` → the jobs matching filter object `f` (below).
  - `exportRows(jobs, fields)` → plain row objects with only the chosen fields.
  - `exportFilename(format, f, when)` → e.g. `Production export - In production - 2026-09-07.xlsx`.
  - `filtersSummary(f)` → the human text used in the log line, the Excel "Export info"
    sheet and the PDF cover.
  - `buildWorkbook(rows, opts)` → an ExcelJS workbook (runs in Node with `require("exceljs")`).
  - `buildDocDefinition(rows, opts)` → a pdfmake document definition object (pure data).
  - `downloadBlob(blob, name)` (browser only, anchor + `URL.createObjectURL`, revoked after).
  Expose on `window.XP`.
- `app.js`: the Export window UI, presets, the log line, wiring the header button.
- `index.html`: `<button class="ghost" id="exportbtn">Export</button>` next to Alerts, the
  two pdfmake script tags before export.js, CSS for the window.
- `test_export.js`.

## Filters (`f`)
```
{ scope: "view" | "ticked" | "sections", sections: [idx...],
  ready: null|true|false, urgent: null|true,
  cp: { win: null|"none"|"process"|"done", drs: ..., glass: ..., prod: ... },
  dates: { sold: {from,to}, ready: {from,to}, floor: {from,to} }  (ISO strings or null),
  county: [..] (exact, case-insensitive), products: [..], glassTypes: [..], sheets: [..],
  hasComments: null|true, hasAlerts: null|true,
  q: "" (same text match as the dashboard search),
  sort: one of the dashboard SORTS keys, desc: bool, groupBySection: bool }
```
`scope:"view"` means the jobs currently shown (the dashboard's `filtered()` result) and
then the filter object applied on top; `"ticked"` = `state.picked`; `"sections"` = the
chosen section indexes. Date presets in the UI: this week, last 7 days, last 30 days,
custom. A live count "N jobs match" updates on every change.

## Fields (the picker; default all on)
job no, customer, county, section, ready to deliver, urgent, dates (five), windows,
doors, windows colour, office no, products F/S/T, glass units, checkpoints, comments,
alerts, notes from the sheet. Never phone, never eircode (not even as an option).

## Excel workbook
- Sheet **Jobs**: one row per job, columns in the Production sheet's own order minus
  PHONE NO. and EIRCODE: Comment | Office no | Job no | Sold | Stamp | Ivana | Ready to
  print | Sent to floor | Customer | Area | Section | Ready to deliver | Urgent | WND | DRS
  | Windows colour | then for every product present in the export three columns
  `<Product> F`, `<Product> S`, `<Product> T` | then one column per glass type present |
  Alerts (count) | Comments (count). Only the ticked fields appear. Real Excel table
  (`ws.addTable`, style TableStyleMedium2-like with `showRowStripes`), frozen header row,
  sensible column widths, real date cells with `dd-mmm-yyyy` format, numbers as numbers.
  Fills mirror the dashboard's meaning and are always paired with a value or word: job-no
  cell green when ready to deliver; product F/S/T and glass cells gold when that
  checkpoint is done, yellow when in process; urgent job-no text in red bold.
- Sheet **Comments**: Job | Source (Sheet comment / Brendan's notes / Specials / Dashboard)
  | Who | When | Text. Sheet **Checkpoints**: Job | Group | Item | Done | Total | Status.
  Sheet **Export info**: exported by, date/time, format, scope, filters summary (one line
  per filter), job count, dashboard build. Sheets only when their field is ticked (Export
  info always).
- If `groupBySection`: the Jobs sheet gets one table per section with a bold section
  heading row above each (or one sheet per section - pick one, say which, keep it simple).

## PDF (pdfmake, A4)
- Fonts: Roboto from `vfs_fonts.js`. Colours: the dashboard's language: gold `#FFE699`
  done, yellow `#FFFF00` in process (use darker text on it), green `#2E7D32` ready to
  deliver, red `#C62828` urgent, neutral greys; every colour paired with a number or word,
  never colour alone (the office has colour-blind readers).
- Header on every page: logo (if `assets/logo.png` was loaded as a data URL by app.js;
  otherwise skipped) + company name (taken from the page `<title>` text before " " or the
  Config sheet key `company` if present, never hard-coded beyond what index.html already
  shows) + "Production export" + date. Footer: page x of y, exported by.
- **Cover / summary page**: title, date, who, the filters summary, then big-number tiles:
  jobs, windows, doors, components (F+S+T), and a small per-section table of counts.
- **Job cards layout** (default): one card per job, at most two per page, never split
  across a page. Card: header band with job number (large), customer, county, section
  badge, "Ready to deliver" or "In production", Urgent badge. Then a row of three large
  numbers with labels: Windows, Doors, Components. Then products: one line per product
  with a stacked horizontal bar (F, S, T segments, each segment labelled with its number)
  drawn with pdfmake `canvas` rectangles sized to the numbers. Then glass units as labelled
  blocks sized by quantity. Then checkpoints: a progress bar per group (Windows, Doors,
  Glass, each product) with "done of total". Then the five dates as a timeline (dots and
  labels, filled when the date exists). Then comments (each with source, who, when) and
  alerts count. Only ticked fields appear.
- **Table layout**: landscape A4, one row per job with the chosen columns, repeated header
  row, zebra rows, section group headings when grouped.
- The document definition must be plain data (no functions except pdfmake's standard
  header/footer functions), so tests can inspect it.

## Export window (app.js)
Header **Export** button → window: Format (Excel / PDF), Layout (PDF only: Job cards /
Table), Scope (What I see now / Ticked jobs (n) / Sections…), Filters (the list above,
compact, collapsible groups), Fields (checkboxes, "all"/"none"), Sort & group, Presets
(save as…, load, delete; localStorage), live count, **Download** (disabled at 0 jobs).
Download: build → `downloadBlob` → `noteChange("(export)", "Export", format + " · " + n +
" jobs", filtersSummary(f))` → toast. Works with the drawer closed; ticking jobs uses the
existing checkboxes. Phone width: the window is full-screen and scrolls.

## Tests (`test_export.js`, vm-loaded real code)
- Each filter parameter individually, and combined; scope modes; the text search.
- Field exclusion: with every field on, assert no output (xlsx cells read back via ExcelJS,
  and every string in the docDefinition, recursively) contains a job's `ph3` value, `eir`
  value, or the words "phone"/"eircode" (fixtures must include distinctive fake values).
- Workbook: sheet names, header order, table present, frozen header, date cells are
  Dates, fills on ready/done/process, urgent styling, Export info content, grouping.
- DocDefinition: cover tiles equal the sums, one card per job, the stacked bar segment
  widths proportional to F/S/T, cards not split (`unbreakable`), table layout columns,
  header/footer present, no logo image when none was given.
- Filename; filtersSummary text; the log line; presets save/load/delete; the count.
- A standing assertion in every test: no `fetch` call happened.
